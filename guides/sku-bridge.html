SKU Bridge — step-by-step user guide

Prepare a product spreadsheet, understand the warnings and download only the rows you have reviewed.

This guide describes the current public web beta. It accepts Excel (.xlsx/.xls) and CSV; Excel uses the first worksheet. The current Download approved rows button produces CSV. A reviewed CSV still needs to match your destination system’s import template.

A few useful words

Column mapping
Telling the tool which source column means SKU, description, price or stock.
READY
A row passed the checks implemented in this beta. It is not a guarantee that all business information is correct.
Approved / USE
Your decision to include a READY row in the download.
Issue flags
Reasons to review a row. A single row can have several flags.

1. Prepare a small practice file

Before opening the tool

What to do

  1. Download the practice CSV from this page. Keep a separate copy of your original business file when using your own data.
  2. Put column names in the first row and one product record on each subsequent row. For Excel, place the intended data on the first worksheet.
  3. Keep SKU and barcode columns as text to preserve leading zeros. Use plain quantities, a consistent decimal format and explicit currencies such as TRY or USD.
  4. Start with a few rows. Prefer Excel for complex cells containing line breaks; the current CSV reader expects a simple comma-separated file.
What you should seeThe practice file contains four rows with deliberate duplicates and missing fields. It contains no customer data.
Keep in mindDo not treat advertised launch-plan limits as enforced technical limits of the current beta. Begin with a small test file.

2. Load the file

1. Add your inventory file

What to do

  1. Open SKU Bridge. Select Choose Excel or CSV and select the practice file. On a computer you can also drag the file onto the upload area.
  2. Check the filename and row count shown under the upload area. For this guide’s practice file you should see 4 rows.
  3. The section 2. Confirm column mapping appears. If you use Load demo file instead, it loads a different six-row example; the counts in this guide will not apply.
What you should seeYour filename, four rows and the mapping dropdowns are visible.
Keep in mindOrdinary file loading and checks run in your browser in this beta. Refresh or Start over clears the current work, so download your reviewed result before leaving.

3. Confirm what each column means

2. Confirm column mapping

What to do

  1. Check SKU / Product code first. Map it to the SKU column; the tool cannot analyze a file without an SKU mapping.
  2. Match Description, Unit of measure, Unit price, Currency, Current stock and Warehouse to their respective source columns. Leave absent optional columns as — Not in file —.
  3. Check the Currency mapping explicitly. This beta fills a blank currency with USD, which may not be the currency you intended.
  4. Select Analyze data. You do not need Analyze & Map with AI to complete this task.
What you should seeThe Data quality report opens with editable rows and issue counts.
Keep in mindThe optional AI mapping button sends column headers and up to 12 sample rows to the configured AI service. Use it only with data you are comfortable sharing. If it fails, manual mapping still works.

4. Read the results before changing anything

3. Data quality report

What to do

  1. Read each row’s STATUS as well as the summary. MISSING_SKU means the product code is missing; MISSING_PRICE means this beta has no unit price for that row.
  2. DUPLICATE_SKU marks repeated codes, including codes that differ only in case. PRICE_CONFLICT means rows for the same code show different prices. INVALID_BARCODE means the current barcode check rejected the supplied value.
  3. In the practice file, DEMO-BOX is the only initially READY row. DEMO-SCREW and demo-screw are duplicates with different prices; the tape row has no SKU or price.
  4. Treat the quality score as a summary of these checks, not a certificate of correct stock, pricing, barcode ownership or ERP compatibility.
What you should seeYou can explain why each of the four rows is ready or needs review. The number of issue flags can exceed the number of rows.
Keep in mindDo not invent a new code, price or barcode merely to remove a warning. Check the source record and the intended business meaning.

5. Correct, recheck and choose rows

Editable results table → Recheck corrections

What to do

  1. For the training tape row only, enter SKU DEMO-TAPE and Unit price 2.00. These are practice values, not suggested business prices.
  2. Select Recheck corrections. The tape row should now be READY. Editing a row clears its approval, so explicitly check its USE box after rechecking.
  3. Review DEMO-BOX and its USE checkbox. Ready rows may already be selected on the first analysis; inspect the checkboxes before export.
  4. Leave the two duplicate screw rows excluded until you decide whether they describe the same product, two distinct products, or stock in separate locations. This beta does not make that business decision or merge them for you.
What you should seeOnly DEMO-BOX and DEMO-TAPE are selected for this practice export. The summary shows 2 approved rows and Download approved rows becomes available.
Keep in mindYou can scroll the result table horizontally to reach PRICE, CURRENCY, STOCK and WAREHOUSE. Excluding a row from the export does not delete it from your original file.

6. Download and inspect the result

Download approved rows

What to do

  1. Confirm the approved count, then select Download approved rows. Look for Hamvara-approved-SKU.csv in your browser’s downloads.
  2. Open the downloaded file using a CSV import dialog where possible. Set SKU and barcode columns to text, rather than allowing Excel to interpret them as numbers.
  3. Verify that the practice output has one header row and two data rows: DEMO-BOX and DEMO-TAPE. Check delimiters, line breaks, codes, quantities, prices and currencies.
  4. Compare the headers and units with your destination system’s template. Import a small batch into a test workspace first; SKU Bridge does not automatically post the file into MRP.
What you should seeYou have a separate reviewed CSV and can explain exactly which rows it contains.
Keep in mindIf the CSV opens as one long line, shows literal backslash characters, loses codes or contains unexpected values, do not import it. Keep the original and send a non-sensitive example to Hamvara support.

Common questions

Download approved rows is disabled.

At least one row must be READY and approved. After editing, select Recheck corrections and check the desired USE boxes again.

The file has a price column, but every row says MISSING_PRICE.

Return to the mapping dropdowns and check Unit price. If you re-run Analyze data from the source file, your table corrections are rebuilt from that source; save a record of your corrections first.

A valid-looking barcode is rejected.

Check the original code, leading zeros and supported barcode format. If it still fails, report it with a non-sensitive example; do not change a real barcode or erase it just to obtain READY.

Can the tool recover leading zeros that Excel already removed?

No reliable recovery is possible without the original code. Correct the source using your master record.

Can I export Excel directly or send to any ERP automatically?

This public beta currently exports CSV. Use the destination ERP’s required template and a test import; the tool does not guarantee universal compatibility.

AI mapping is unavailable.

Choose the columns manually and select Analyze data. AI is optional for this workflow.

Later: larger files and AI assistance

After the sample succeeds, use a small copy of your own file. Review mapping, number formats and destination rules each time. For additional guidance, the help center can prepare a question for ChatGPT; do not include access keys or confidential files.
